# Mini Agent —— 从零实现的最小可用 Agent

一个**不依赖任何 Agent 框架**（langgraph / langchain / openhands 都不用）、核心逻辑全部手写的最小可用 Agent。能调用工具、能记住上下文、能多会话隔离、能压缩长对话，并用真实大模型 API 驱动。

> 题目：Vibe coding —— 从零实现一个最小可用 Agent。

- 🔗 代码仓库：https://github.com/xyyyyi-x/mini-agent
- 🎬 演示录屏：https://www.bilibili.com/video/BV1Wn326vEPo/

## 一、怎么运行（从这里开始）

### 第 0 步：装依赖

```bash
pip install -r requirements.txt
# 等价于：pip install openai gradio pytest
```

### 第 1 步：配置大模型 API Key

项目用 `openai` 这个库当"传话筒"，所以**任何 OpenAI 兼容的大模型都能用**。复制 `.env.example` 为 `.env`，填入你的 key：

```bash
cp .env.example .env
```

推荐用 **DeepSeek**（便宜、不限流、中文好、响应 1–3 秒）：
```ini
LLM_API_KEY=sk-你的deepseek_key
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-chat
```
（也支持智谱 GLM、OpenAI，模板见 `.env.example`。）

### 第 2 步：跑起来（三种方式，任选）

**方式 A：双击启动器（最省心，Windows 推荐）**
- 双击 **`run_cli.bat`** → 终端聊天（最稳，不挑环境）。
- 双击 **`run_web.bat`** → 网页版，按它打印的地址 `http://127.0.0.1:7860` 用浏览器打开。

这两个 `.bat` 会自动把控制台和 Python 切成 UTF-8，**解决 Windows 下中文乱码/报错的老毛病**。

**方式 B：命令行启动**
```bash
python -m mini_agent.cli     # 终端版
python -m mini_agent.app     # 网页版（Gradio）
```
> Windows 上如果命令行方式中文报错，请改用上面的 `.bat`，或加 `-X utf8`：`python -X utf8 -m mini_agent.cli`。

**方式 C：跑测试（验证一切正常）**
```bash
python -m pytest            # 全部测试（不联网，秒级）
```

### 终端版怎么用（录屏示例）

```
你 > 北京天气怎么样？
Agent > 北京今天晴，气温 32°C。
  ↳ 本轮工具调用：['weather']

你 > 帮我记个待办：买牛奶
Agent > 已记下待办：买牛奶（编号 #1）。
  ↳ 本轮工具调用：['todo']

你 > /new 周报            ← 新建一个独立会话
你 > 算一下 17 乘以 23
Agent > 17 乘以 23 等于 391。
  ↳ 本轮工具调用：['calculator']

你 > /switch 会话1        ← 切回旧会话，接着聊（历史还在）
你 > /quit                ← 退出
```

网页版同理，只是界面换成浏览器，左侧可以新建/切换/删除会话，底部能展开看每一步的思考与工具调用（Trace）。

## 二、系统设计（大白话版）

### 一句话概括

把大模型想象成一个**很聪明、但只会"动嘴"的新员工**。它自己不会真去算数、查天气，所以你给它三样东西：

1. **工具箱**：几样真能干活的工具（计算器、搜索、天气、待办）。
2. **一本说明书**：告诉它每个工具叫什么、能干啥、用的时候要填什么参数。
3. **一个固定的汇报格式**：让它每次都用统一格式告诉你"我在想啥、要用哪个工具、还是直接回答"。

然后让它**循环干活，直到能回答用户为止**。

### 核心循环（就是题目说的 "loop"）

用户每说一句话，Agent 最多重复这几步 8 次：

```
① 接收用户输入
② 把"说明书 + 之前的对话"一起发给大模型，让它判断：
    - 直接回答？还是调一个工具？
③ 如果要调工具 → 真的去执行，拿到结果
④ 看结果：还不够？回到 ② 继续；够了 → 把答案告诉用户，结束
```

**举个多步的例子**（用户说"先算 17×23，再记个待办：周五开会"）：

| 第几圈 | 大模型判断 | 执行 | 结果 |
|---|---|---|---|
| 第 1 圈 | 要算数 | 计算器(17*23) | `391` |
| 第 2 圈 | 要记待办 | 待办.add(周五开会) | `已添加 #1` |
| 第 3 圈 | 两件事都办完了 | （不调工具） | 直接回答用户 |

第 3 圈才回用户："17×23=391，待办已记。" 这就是 loop——**转几圈不固定，看任务多复杂**。

> 为什么要有上限（8 次）和"重复调用检测"？防止大模型陷进"调工具 → 不满意 → 又调同一个工具"的死循环。

### 工具 + 注册机制（题目重点）

每个工具自带三件套，像贴在工具上的标签：

| 标签 | 含义 | 例 |
|---|---|---|
| **名称** | 工具叫啥 | `calculator` |
| **描述** | 能干啥 | "数学计算器，输入算式返回结果" |
| **参数 Schema** | 用时要填什么表 | "必须填一栏 `expr`（算式）" |

这些标签被**原样塞进发给大模型的提示词**里。大模型读着这些标签**自己决定**用哪个工具、填什么参数——你不用写"如果问乘法就用计算器"这种死规则。这就是"基于 Schema 自主决策"。

> 本项目 4 个工具：`calculator`（安全求值，挡代码注入）、`search`（mock）、`weather`（mock）、`todo`（每个会话独立）。

### 解析大模型的输出（题目重点）

大模型每次按约定回一段 JSON：
```json
{"thought":"用户要算乘法，用计算器","action":"calculator","action_input":{"expr":"17*23"},"final_answer":null}
```
我们自己写代码把它**拆成四块**：思考过程(`thought`)、工具调用(`action`)、参数(`action_input`)、最终答案(`final_answer`)。拆完才知道下一步干嘛。

> 这个"拆"是**手写的**（`parser.py`，5 级降级兜底），没用大模型厂家自带的"函数调用"功能——那样就不算"从零实现"了。

### 多会话（窗口之间互不干扰）

每个会话 = 一个独立的 JSON 文件（`sessions/用户__窗口.json`），里面装着这个会话的对话历史和待办。两个窗口是两个文件，**天然不串**；关掉程序再开，从文件读回来，**接着聊**。

### 异常处理 + 执行日志

- 工具出错 → 错误信息当结果喂回去，大模型会自己换思路。
- 整个流程崩了 → 给用户一句可读的"请重试"，不会白屏。
- 每一轮的"思考/工具/结果"都记进 `logs/trace.jsonl`，网页底部也能看。

## 三、记忆（Memory）的召回时机与放置方式

> 这是题目特别要求讲清楚的点。这里的"记忆"= Agent 记住上下文的能力。

### 1. 一条对话里，"记忆"长什么样？

每次发给大模型的内容（叫 **context**），由几部分**按固定顺序**拼成：

```
┌─ ① 系统提示词（角色 + 工具说明书 + 输出格式）
├─ ② 旧对话的摘要（只有对话很长、被压缩过才会出现）
└─ ③ 最近的对话轨迹（按时间排）：
        用户：北京天气？
        助手：Thought: 查天气 / Action: weather
        用户：Observation(weather): 北京 晴 32°C        ← 工具结果，关键
        助手：Thought: 得到结果 / Final Answer: 北京晴 32°C
        用户：帮我记个待办：买牛奶                      ← 当前这句就是最后一条
```

### 2. 什么时候"召回"（重新拼这份记忆）？

**在循环的每一圈、每次问大模型之前，都重新拼一次。** 不是一句话只拼一次。

为什么？因为一句话可能要调好几次工具，每次拿到新结果，都得把最新结果塞进记忆，大模型才能基于最新情况继续判断。

> 代码位置：`runtime.py` 里每次调大模型前都先 `build_messages()`。

### 3. 往记忆里放什么？什么不放？

- ✅ **用户每句话**：当然要。
- ✅ **Agent 的思考与动作**（`Thought/Action/Action Input`）：让它记得自己上一步干了啥。
- ✅ **工具的结果**（`Observation`）：**最关键**。比如用户先"记待办：买牛奶"，再问"我刚记了啥"，Agent 靠的就是上一轮这条 `Observation`。
- ✅ **旧对话摘要**：太长时，老消息压缩成一段摘要留着要点。
- ❌ 不放 API Key、不放大模型的底层 HTTP 细节（安全）。

### 4. 记忆太长怎么办？（基础压缩）

每次拼记忆前先检查，**超过阈值才压缩**：
- 触发：消息超过 20 条，或估算 token 超过 3000。
- 做法：把最旧的消息赶出去，交给大模型**压成一段摘要**（和上一次摘要合并），只留最近 8 条原文。
- 兜底：压缩后如果还是太长，就从最旧的开始一条条丢。

> 说明：大模型没有好用的本地分词器，token 用"字符数 ÷ 4"粗估，够用且不引额外依赖。待办这类**状态**存在单独的地方（不放在对话消息里），所以压缩永远不会丢待办。

### 5. 怎么支持"追问"？

- **纯对话追问**（先"我叫张三"，再"我叫啥"）：靠记忆里保留的历史对话。
- **带工具的追问**（先"记待办：买牛奶"，再"我刚记了啥"）：靠记忆里保留的工具结果 `Observation`。
- 两种都靠"把完整轨迹写进记忆、跨轮保留"，只有超长时才被压成摘要。

## 四、"从零实现"的边界（手写了啥，用了啥）

**手写（核心，没用任何 Agent 框架）**：主循环、输出解析、上下文管理与压缩、会话与持久化、工具注册与全部工具、执行日志。

**只当通用基础设施用（不是 Agent 框架）**：
- `openai`：仅当 HTTP 客户端，调用 OpenAI 兼容接口（DeepSeek/智谱等）。工具决策和循环都是我们自己解析 JSON 实现的，没用它的 function-calling。
- `gradio`：仅做网页界面。
- `pytest`：仅做测试。

## 六、常见问题（FAQ）

**Q：网页版打不开 / "无法建立连接"。**
多半是端口被占，或 Windows 中文编码问题。用 `run_web.bat` 启动（它会自动处理编码并找空闲端口），地址用 `http://127.0.0.1:7860`（别用 `localhost`，避免 IPv6 连不上）。启动失败时窗口会停住显示完整报错。

**Q：终端版中文乱码或报 `UnicodeEncodeError`。**
用 `run_cli.bat`（自动 UTF-8）。或 `python -X utf8 -m mini_agent.cli`。

**Q：大模型调用很慢/偶尔失败。**
如果是智谱 Coding Plan，它有速率限制，每条消息间隔 1–2 秒即可；失败会快速提示"请重试"，稍后再试。换 DeepSeek 通常更快更稳。

**Q：用什么模型最好？**
推荐 `deepseek-chat`（DeepSeek-V3）。指令跟随好、能稳定输出 JSON、中文好、便宜。`deepseek-reasoner`（R1）也能用但更慢。

**Q：怎么验证我的 key 能用？**
```bash
python -m pytest mini_agent/tests/test_integration_real_api.py -v
```
（没配 key 会自动跳过；配了会真调一次"17×23"和"北京天气"。）
